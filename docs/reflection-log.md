## 13.09.2026 – Marian

### Deltaker(e)
Marian

### Fase
Tidlig idémyldring og vurdering av prosjekt

### Oppgave
Begynne å undersøke hvilke prosjektideer som kan være aktuelle for IBE160.

### Utgangspunkt
Vi kom litt sent i gang med prosjektarbeidet og hadde derfor ikke bestemt prosjektidé enda. Målet denne dagen var å få bedre oversikt over kravene i emnet og finne en idé som kunne være interessant, men samtidig realistisk å gjennomføre for en gruppe på to personer.

### Hva gjorde vi?
- Lastet Appendix A inn i ChatGPT for å få bedre oversikt over verktøyene og det tekniske oppsettet som brukes i emnet.
- Lastet inn dokumentet med prosjektforslagene fra faglærer.
- Gikk gjennom og vurderte ulike prosjektalternativer.
- Ble inspirert av å høre om en Escape Room-idé og begynte å tenke på om vi kunne lage noe med gåter, spor og problemløsning.
- Dette utviklet seg videre til ideen «Mistenkt», der brukeren kan undersøke informasjon og spor for å løse et mysterium.
- Vurderte også en annen retning: en applikasjon som bruker KI til å analysere informasjon om aksjer og hjelpe brukeren med å forstå og vurdere informasjonen.
- Sammenlignet egne ideer med faglærerens prosjektforslag.
- Brukte ChatGPT til idémyldring rundt de ulike alternativene.
- Prosjektvalg ble ikke bestemt denne dagen.

### KI-verktøy brukt
ChatGPT.

### Viktige prompts
Spørsmålene handlet hovedsakelig om:
- om «Mistenkt» kunne egne seg som prosjekt i IBE160
- hvordan en Escape Room-inspirert idé kunne utvikles videre
- om et aksjerelatert KI-prosjekt kunne være aktuelt
- hvilke fordeler, ulemper og tekniske utfordringer de ulike alternativene kunne ha
- hvordan egne ideer kunne sammenlignes med faglærerens prosjektforslag

Viktige hele prompts kan senere lagres i `docs/ai-prompts/` dersom de skal brukes som dokumentasjon i refleksjonsrapporten.

### Hva foreslo KI?
- Å vurdere prosjektideene ut fra omfang, vanskelighetsgrad, KI-bruk og gjennomførbarhet.
- Å ikke låse prosjektet for tidlig før alternativene var sammenlignet.
- Å bruke KI som sparringspartner i idéfasen, men beholde den endelige beslutningen i gruppen.

### Hva valgte vi å bruke eller endre selv?
- Vi bestemte oss for å ikke velge prosjekt med en gang.
- Vi ønsket først å tenke og idémyldre hver for oss.
- Deretter skulle vi bruke KI til å sammenligne de mest aktuelle alternativene etter at vi selv hadde vurdert dem.
- Vi beholdt både «Mistenkt», aksjeideen og faglærerens prosjektforslag som aktuelle alternativer.

### Videre plan
Vi vil blant annet vurdere:
- hvor interessant prosjektet er for oss
- om det er realistisk å gjennomføre for to personer
- vanskelighetsgrad og arbeidsmengde
- hvor godt prosjektet passer til Programmering med KI
- hvor naturlig KI kan brukes som en del av løsningen
- muligheter for testing og videreutvikling
- tekniske utfordringer og risiko
- om prosjektet gir nok innhold til refleksjonsrapporten

Planen er at vi først gjør egne vurderinger og deretter bruker ChatGPT til å diskutere og sammenligne alternativene. KI skal være et hjelpemiddel i beslutningen, men ikke ta beslutningen for oss.

Når prosjektet er valgt og avgrenset, går vi videre til `proposal.md` og deretter BMAD-arbeidet med blant annet Product Brief og videre planlegging.

### Problemer eller feil
Ingen tekniske problemer denne dagen. Utfordringen var først og fremst at vi kom litt sent i gang og derfor måtte få rask oversikt over prosjektkrav og alternativer.

### Hvordan ble problemet løst?
Vi samlet kursmaterialet, gikk gjennom prosjektforslagene og brukte ChatGPT til å strukturere idémyldringen før vi tok en beslutning.

### Hva lærte vi?
- At idéfasen også er en viktig del av utviklingsprosessen.
- At KI kan brukes til å utforske og sammenligne ideer raskt.
- At gruppen selv må vurdere hva som er realistisk og ta den endelige beslutningen.
- At prosjektvalget påvirker både arbeidsmengde, tekniske krav og hva vi senere kan reflektere over.

## 15.09.2026 – Marian

### Fase
Oppsett av utviklingsmiljø og prosjekt

### Oppgave
Gjøre PC og GitHub-repository klart for IBE160-prosjektet og installere BMAD.

### Hva gjorde vi?
- Installerte og kontrollerte Git.
- Installerte og kontrollerte VS Code og nødvendige utvidelser.
- Installerte Node.js LTS og npm.
- Installerte uv og Python 3.12.
- Installerte Docker Desktop og WSL2.
- Testet Docker med `docker run hello-world`.
- Installerte og logget inn i Claude Code.
- Installerte GitHub CLI og logget inn på kurskontoen.
- Klonet repositoryet `IBE160-2026/G74-lund-osen`.
- Konfigurerte Git med Marian sin egen Git-identitet.
- Installerte BMAD i prosjektet.
- Valgte BMad Method og BMad Creative Intelligence Suite.
- Valgte Claude Code og Codex som integrasjoner.
- Satte BMAD til norsk chat og norsk dokumentutdata.
- Satte BMAD-navn til `Lund og Osen`.
- Brukte `_bmad-output` som standard mappe for BMAD-dokumenter.
- Opprettet en egen refleksjonslogg og mal for lagring av viktige KI-prompts.
- Fortsatte å se Panopto-opptak og vurdere prosjektalternativene.

### KI-verktøy brukt
ChatGPT ble brukt som stegvis veiledning under installasjonen og oppsettet.

Claude Code ble installert og testet for senere bruk i prosjektet.

### Viktige prompts
Veiledningen bestod hovedsakelig av spørsmål om hvilke programmer som skulle installeres, hvilke valg som skulle tas, og kontroll av feilmeldinger og installasjonsresultater.

### Hva foreslo KI?
- Rekkefølge for installasjon.
- Hvordan rette npm-problemet i PowerShell.
- Hvordan aktivere WSL2 slik at Docker kunne starte.
- Hvordan autentisere Claude Code og GitHub CLI.
- Hvordan installere og konfigurere BMAD i riktig repository.
- Å opprette en løpende refleksjonslogg og egen mappe for viktige KI-prompts.

### Hva valgte vi å bruke eller endre selv?
- Vi valgte norsk som samtale- og dokumentutdataspråk i BMAD.
- Vi valgte gruppenavnet `Lund og Osen`.
- Vi valgte både Claude Code og Codex som BMAD-integrasjoner.
- Vi valgte Creative Intelligence Suite som ekstra BMAD-modul.
- Vi valgte å dokumentere prosjektarbeidet fortløpende i Git-repositoryet.

### Hvorfor valgte vi ekstra BMAD-verktøy?
I tillegg til selve BMad Method valgte vi BMad Creative Intelligence Suite. Dette var ikke nødvendig for grunnoppsettet, men kan være nyttig i idé- og planleggingsfasen når vi skal vurdere ulike prosjektideer, brainstorme og utvikle ideen videre.

Vi valgte også integrasjon med både Claude Code og Codex. Hensikten er å ha mulighet til å bruke og sammenligne flere KI-verktøy i prosjektarbeidet, i stedet for å være avhengig av bare ett.

Dette kan være nyttig uansett om vi velger «Mistenkt», et aksjerelatert prosjekt eller et av faglærerens prosjektforslag.


### Valg av KI-verktøy videre
I starten av prosjektarbeidet brukte vi hovedsakelig ChatGPT. Vi hadde allerede tilgang til ChatGPT, mens Claude først ble kjøpt og gjort tilgjengelig for oss 15.09.2026. Det var derfor naturlig å bruke ChatGPT i oppstarts- og idéfasen til å forstå kursmaterialet, vurdere prosjektideer og få hjelp med det tekniske oppsettet.

Etter at Claude Code ble installert og satt opp, planlegger vi å bruke Claude Code mer aktivt når vi går videre med BMAD, prosjektfiler, programmering, testing og feilretting. Claude Code er bedre egnet til denne delen fordi det kan arbeide direkte i prosjektets repository og med filene i prosjektet.

Vi vurderer også å bruke både ChatGPT og Claude på enkelte utvalgte oppgaver for å se om de gir forskjellige forslag eller løsninger. Hensikten er ikke å gjøre alt dobbelt, men å sammenligne verktøyene når det kan gi læring eller påvirke en viktig beslutning.

Aktuelle sammenligningspunkter kan være:
- valg og avgrensing av prosjekt
- Product Brief og andre BMAD-dokumenter
- arkitektur og tekniske valg
- problemløsning og feilretting
- forslag til testing og forbedringer

Hvis verktøyene gir ulike forslag, vil vi dokumentere forskjellene og begrunne hvilken løsning vi velger. Dette kan gi grunnlag for refleksjon over kvaliteten på KI-svar, hvor pålitelige verktøyene er og hvordan vi selv må vurdere forslagene før de brukes.

### Problemer eller feil
- npm ble først blokkert av PowerShell sin policy for scripts.
- Docker kunne først ikke starte fordi virtualiseringsstøtte via WSL2 ikke var klar.
- Claude Code-innloggingen krevde korrekt autentiseringsflyt og kode.
- Første forsøk på å lime autentiseringskode ble tolket som en PowerShell-kommando.

### Hvordan ble problemet løst?
- Node.js LTS ble installert på nytt, og npm fungerte etterpå.
- WSL2 ble installert/aktivert, og Docker ble testet med `hello-world`.
- Claude Code ble autentisert på nytt gjennom nettleser og terminal.
- GitHub CLI ble autentisert med nettleser.

### Hva lærte vi?
- Forskjellen mellom lokal programvare, prosjektfiler og GitHub-repository.
- At BMAD installeres per repository og ikke som et vanlig globalt program.
- Hvordan Git brukes til å dokumentere og dele prosjektendringer.
- Hvordan Docker, WSL2, Claude Code, BMAD og GitHub henger sammen i utviklingsmiljøet.
- At ekstra verktøy ikke nødvendigvis er påkrevd, men kan velges dersom vi har en tydelig grunn til å bruke dem.
- At løpende logging gjør det enklere å dokumentere KI-bruk og arbeidsfordeling senere.

### Videre plan
Vi har fortsatt ikke bestemt endelig prosjekt. Neste steg er at Marian og Joakim tenker og idémyldrer hver for seg, og deretter sammenligner vi de mest aktuelle prosjektalternativene.

Etter våre egne vurderinger vil vi bruke KI som sparringspartner for å diskutere hvilket prosjekt som er mest egnet. Vi vil særlig vurdere «Mistenkt», et aksjerelatert prosjekt og relevante prosjektforslag fra faglærer.

Først når prosjektet er valgt og avgrenset, går vi videre med `proposal.md` og deretter BMAD-prosessen.
